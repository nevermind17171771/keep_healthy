# KEEP HEALTHY 4.0

개인 운동 기록 앱의 전체 재구현입니다. 기존 GitHub Pages 앱에서 사용하던 운동 사전과 루틴을 바탕으로, 기록·근육 지도·기구 설정·분석·계정 저장을 연결했습니다.

현재 상태는 **비공개 출시 후보**입니다. 이 브랜치는 GitHub Pages용 정적 HTML이 아니라 Cloudflare Workers + D1 기반 앱입니다. 기존 `main`의 서비스를 교체하기 전에 새 앱에서 기록 이관과 실기기 사용을 확인해야 합니다.

## 사용할 수 있는 기능

- 382개 중복 제거 운동, 15개 기본 루틴, 이름·초성·부위·장비 검색, 즐겨찾기
- 앞·뒷면 근육 도식과 주동근/보조근 구분. 광배근, 등 상부, 전면/측면/후면 삼각근의 분류 개선
- 중량·맨몸 추가 중량·보조 중량·시간·유산소 기록 방식 구분
- 워밍업·본세트·드롭세트, RPE, 슈퍼세트, 지난 기록, 휴식 타이머와 일시정지
- 기구별 중량 이력, 좌석/그립 메모, 최소 증량 단위, 보수적인 다음 중량 제안
- 루틴 생성·복제·편집, 주간 계획, 과거 운동 입력·수정·삭제·복원
- 주간 본세트, 부위별 세트 분포, 종목/기구별 추정 1RM, 실제 신체 기록과 별도 목표 체중
- JSON 가져오기/백업, CSV, 오운완 카드 다운로드
- IndexedDB 임시 저장, 계정별 D1 저장, 충돌 감지·합치기, 미완료 운동 복구본, 일별 변경 전 백업
- 모바일 레이아웃, 다크/라이트 테마, 홈 화면 설치, 오프라인 앱 캐시, 운동 종료 후 업데이트

## 기존 기록 가져오기

1. 기존 앱에서 **내보내기**를 눌러 JSON 백업을 받습니다.
2. 새 앱의 **설정·데이터 → 기록 가져오기**에서 파일을 선택합니다.
3. 운동/신체 기록 수를 확인하고 **백업 후 합치기**를 누릅니다.
4. 기존 운동 몇 건의 날짜·세트·시간을 비교합니다. 동기화 완료를 확인한 후 새 앱을 홈 화면에 추가합니다.

새 주소에서 기존 주소의 기기 저장소를 직접 읽을 수 없으므로 파일 이관이 필요합니다. 원본 JSON은 `legacyArchive`로 보관합니다. 기존 앱의 유산소 지표(경사, 칼로리, 층 수 등)는 해당 입력 필드로 옮기며 원본도 보관합니다. 영양·수분 기록은 원본에 보관되며 별도 입력/분석 화면은 제공하지 않습니다. 이전 버그로 숫자가 된 `20:30`의 초 단위는 이미 소실되어 복구할 수 없습니다. 원본에서 단위가 초인 종목과 미터인 거리는 별도로 변환합니다.

## 개발과 검증

Node.js 24 기준입니다.

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run test:worker
```

- `npm test`: 데이터 변환·계산·충돌·API 접근 통제와 7개 화면 렌더링을 검증합니다.
- `test:worker`: 빌드 결과를 실제 Workers 런타임(Miniflare)에서 실행하고 D1 마이그레이션, 익명 접근 거부, 인증된 저장/조회, HTML 진입점을 검증합니다.
- `wrangler.local.json`: 로컬 타입 생성 및 D1 마이그레이션용 설정입니다. 실제 사용자 데이터나 비밀키를 포함하지 않습니다.
- 배포는 Sites 관리 환경을 사용합니다. `.openai/hosting.json`의 논리적 D1 바인딩 `DB`를 유지합니다.
- `release/keep-healthy-v4`는 기존 Git 이력을 이어받습니다. 이전 앱의 소스는 Git 이력에서 조회할 수 있습니다.

## 출시 전 남은 확인

브라우저 접근 정책으로 실제 클릭·화면 크기별 시각 QA는 수행하지 못했습니다. 서버 렌더링 테스트는 실기기 E2E 테스트를 대체하지 않습니다. iOS Safari/Android Chrome에서 설치, 숫자 입력, 화면 잠금 후 복귀, 오프라인 재실행, 업데이트, 두 기기 충돌을 확인해야 합니다.

현재 동기화는 계정의 전체 상태를 보내며 요청 크기는 1.5MB로 제한됩니다. 큰 기록집은 백업 파일을 유지해야 하며, 장기 대용량 서비스에는 세션별 증분 동기화와 저장 구조 확장이 필요합니다. 로컬 기록은 해당 브라우저에 남으므로 개인 기기 사용을 전제로 합니다. PWA는 네이티브 백그라운드 알림이나 워치 연동을 제공하지 않습니다. 외부 AI, 결제, 건강 플랫폼 연동은 구현된 것처럼 표시하지 않습니다.

운동 설명과 근육 분류는 기록을 돕는 참고 정보입니다. 부위별 세트 수는 실제 근육 자극량이나 회복 진단이 아닙니다. 근육 도식의 세부 구획 한계와 출처는 [운동 데이터 설명](docs/exercise-data.md)을 참고하세요.

### 4.1 운동 중 편의 기능

- 휴식 종료 시 세 번 울리는 복싱 라운드 벨. 기기에서 합성하며 외부 오디오 다운로드가 없습니다. 설정에서 미리 들을 수 있습니다. 모바일 백그라운드 오디오를 보장하지 않습니다.
- 운동 상세와 진행 화면에서 종목명으로 YouTube 쇼츠 검색을 엽니다. 영상은 삽입하지 않으며 검색 결과가 쇼츠로만 제한되지는 않습니다. 필요하면 YouTube에서 Shorts 필터를 선택합니다.
- 트레드밀/인클라인/천국의 계단/사이클/로잉 등 기구별 입력. 단위는 화면에 표시하며 로잉 거리는 m, 저장·CSV 거리는 km로 통일합니다.
- 칼로리·수직 이동거리 등은 기구 표시값을 직접 기록합니다. 미입력과 0을 구별하고 추정값을 자동 생성하지 않습니다. 구간을 추가할 때 속도·경사·레벨만 이어받고 이전 구간의 누적 수치는 복사하지 않습니다.
- 추가 지표는 JSON/CSV, 기록 상세, 지난 기록, 서버 동기화에 포함됩니다. 기존 v4 클라이언트가 모르는 지표를 누락해 전송해도 서버의 해당 세트 지표를 유지하며, 최신 클라이언트의 명시적 빈 객체는 삭제로 인정합니다.
